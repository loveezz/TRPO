# Практическое занятие 1, 2

Веб-приложение для подбора кандидатов на вакантные должности. Проект написан на Go + Fiber, хранит данные в PostgreSQL и работает через HTML-формы.

## Запуск

```bash
docker compose up -d --build
```

После запуска:

- приложение: http://localhost:8000
- pgAdmin4: http://localhost:5050

Демо-вход в приложение:

- email: `admin@example.com`
- пароль: `admin123`

В pgAdmin4:

- email: `admin@example.com`
- пароль: `admin123`

Для подключения к базе в pgAdmin4:

- Host name/address: `db`
- Port: `5432`
- Maintenance database: `candidates_db`
- Username: `candidate_user`
- Password: `candidate_pass`

## Как приложение подключается к базе данных

Подключение к PostgreSQL выполняется при запуске сервера в файле `cmd/server/main.go`.

Приложение читает настройки из `internal/config/config.go`. Главная настройка базы данных называется `DATABASE_DSN`. В Docker Compose она задана так:

```text
host=db user=candidate_user password=candidate_pass dbname=candidates_db port=5432 sslmode=disable TimeZone=Asia/Yekaterinburg
```

Это значит:

- `host=db` - имя контейнера PostgreSQL внутри Docker-сети;
- `user=candidate_user` - пользователь базы данных;
- `password=candidate_pass` - пароль пользователя;
- `dbname=candidates_db` - имя базы данных;
- `port=5432` - внутренний порт PostgreSQL.

Работу с базой выполняет библиотека GORM. В файле `internal/database/postgres.go` открывается соединение, а дальше оно передается в репозиторий:

```go
repo := &repository.Repository{DB: db}
```

Репозиторий находится в `internal/repository/repository.go`. Именно там собраны основные операции с базой: поиск, добавление, редактирование, удаление кандидатов и вакансий.

## Как создаются таблицы

При старте приложения вызывается `AutoMigrate`:

```go
db.AutoMigrate(&models.User{}, &models.Candidate{}, &models.Vacancy{}, &models.Skill{})
```

GORM смотрит на структуры из `internal/models/models.go` и автоматически создает недостающие таблицы в PostgreSQL.

В проекте используются такие таблицы:

- `users` - пользователи для входа в систему;
- `candidates` - кандидаты;
- `vacancies` - вакансии;
- `skills` - справочник навыков;
- `candidate_skills` - связь кандидатов и навыков;
- `vacancy_skills` - связь вакансий и навыков.

SQL-вариант схемы также лежит в `sql/schema.sql`. Он нужен для просмотра структуры вручную или для отчета.

## Таблица users

Таблица `users` нужна только для авторизации.

Основные поля:

- `id` - первичный ключ;
- `full_name` - имя пользователя;
- `email` - email для входа, уникальное поле;
- `password_hash` - хеш пароля;
- `created_at` - дата создания записи.

Пароль не хранится открытым текстом. При создании пользователя пароль `admin123` превращается в bcrypt-хеш через функцию `service.HashPassword`.

При входе приложение:

1. Берет email и пароль из формы `/login`.
2. Ищет пользователя через `FindUserByEmail`.
3. Сравнивает пароль с хешем через `service.CheckPassword`.
4. Если данные верные, создает cookie-сессию `hr_session`.

## Таблица candidates

Таблица `candidates` хранит данные специалистов.

Основные поля:

- `id` - первичный ключ кандидата;
- `full_name` - ФИО;
- `age` - возраст;
- `gender` - пол;
- `email` - контактный email;
- `phone` - телефон;
- `city` - город;
- `position` - желаемая должность;
- `experience_years` - опыт в годах;
- `education` - образование;
- `employment_type` - тип занятости;
- `salary_expectation` - ожидаемая зарплата;
- `about` - дополнительная информация;
- `created_at`, `updated_at` - даты создания и изменения.

Навыки кандидата не хранятся прямо в этой таблице. Они связаны через таблицу `candidate_skills`.

## Таблица vacancies

Таблица `vacancies` хранит вакансии и параметры подбора.

Основные поля:

- `id` - первичный ключ вакансии;
- `title` - название вакансии;
- `department` - отдел;
- `city` - город;
- `employment_type` - тип занятости;
- `min_experience` - минимальный опыт;
- `education_level` - требуемое образование;
- `salary_min` и `salary_max` - зарплатная вилка;
- `description` - описание;
- `requirements` - требования;
- `is_active` - активна ли вакансия;
- `created_at`, `updated_at` - даты создания и изменения.

Навыки вакансии связаны через таблицу `vacancy_skills`.

## Таблица skills

Таблица `skills` является справочником навыков.

Поля:

- `id` - первичный ключ;
- `name` - название навыка, например `Python`, `PostgreSQL`, `Docker`.

Поле `name` уникальное. Это нужно, чтобы один и тот же навык не создавался много раз.

Например, если у трех кандидатов есть навык `Python`, в таблице `skills` будет одна запись `Python`, а связи с кандидатами будут храниться отдельно.

## Таблицы candidate_skills и vacancy_skills

Это промежуточные таблицы для связи многие-ко-многим.

Один кандидат может иметь много навыков. Один навык может принадлежать многим кандидатам. Поэтому связь хранится не в `candidates`, а в отдельной таблице `candidate_skills`.

`candidate_skills` содержит:

- `candidate_id` - ID кандидата;
- `skill_id` - ID навыка.

То же самое для вакансий:

- одна вакансия может требовать много навыков;
- один навык может требоваться в разных вакансиях.

Для этого используется таблица `vacancy_skills`:

- `vacancy_id` - ID вакансии;
- `skill_id` - ID навыка.

## Как добавляются и редактируются кандидаты

Форма кандидата находится на страницах:

- `/candidates/new` - добавление;
- `/candidates/:id/edit` - редактирование.

Обработчики находятся в `internal/handlers/handlers.go`:

- `CreateCandidate` - создание кандидата;
- `UpdateCandidate` - обновление кандидата;
- `DeleteCandidate` - удаление кандидата.

Когда пользователь сохраняет форму, функция `candidateFromForm` собирает данные из полей формы в структуру `models.Candidate`.

После этого вызывается:

```go
a.Repo.SaveCandidate(&candidate, service.NormalizeSkills(c.FormValue("skills")))
```

`NormalizeSkills` разбирает строку навыков, введенную через запятую. Например:

```text
Python, FastAPI, PostgreSQL
```

превращается в список:

```text
Python
FastAPI
PostgreSQL
```

Повторы удаляются, пустые значения игнорируются.

Дальше `SaveCandidate` сохраняет самого кандидата и обновляет его связи с навыками.

## Как сохраняются навыки

За сохранение навыков отвечает функция `ensureSkills` в `internal/repository/repository.go`.

Она работает так:

1. Получает список названий навыков.
2. Для каждого навыка ищет запись в таблице `skills`.
3. Если навык уже есть, использует существующую запись.
4. Если навыка нет, создает новую запись.
5. Возвращает список навыков для связи с кандидатом или вакансией.

После этого GORM обновляет связи:

```go
tx.Model(c).Association("Skills").Replace(skills)
```

Для кандидата это означает: старый список навыков заменяется новым списком из формы.

## Как подгружаются тестовые кандидаты

Тестовые данные загружаются автоматически при старте приложения. За это отвечает файл `internal/seed/seed.go`.

В `cmd/server/main.go` после подключения к базе вызывается:

```go
seed.Run(db)
```

Функция `Run` сначала создает администратора для входа:

```text
admin@example.com / admin123
```

Потом она проверяет количество кандидатов:

```go
db.Model(&models.Candidate{}).Count(&count)
```

Если кандидаты уже есть, тестовые данные повторно не добавляются. Это защищает базу от дублирования записей при каждом перезапуске приложения.

Если кандидатов нет, создается демонстрационный набор:

- Иван Петров;
- Мария Соколова;
- Алексей Морозов;
- Елена Волкова;
- Дмитрий Орлов;
- Ольга Белова;
- Сергей Кузнецов;
- Наталья Федорова.

Для каждого кандидата указываются основные поля и список навыков. Кандидат сохраняется через `repo.SaveCandidate`, поэтому навыки также автоматически попадают в таблицы `skills` и `candidate_skills`.

После кандидатов создаются две тестовые вакансии:

- `Python Backend Developer`;
- `Python Developer (Remote)`.

Они сохраняются через `repo.SaveVacancy`, поэтому их навыки попадают в `skills` и `vacancy_skills`.

## Почему тестовые данные не появляются повторно

В начале `seed.Run` есть проверка:

```go
if count > 0 {
    return nil
}
```

Если в таблице `candidates` уже есть хотя бы одна запись, функция завершает работу. Поэтому при повторном запуске контейнера старые кандидаты остаются, но новые копии не создаются.

Если нужно заново получить чистые тестовые данные, можно удалить Docker volume с базой данных:

```bash
docker compose down -v
docker compose up -d --build
```

После удаления volume база создастся заново, и seed снова заполнит ее тестовыми данными.

## Как работает фильтр кандидатов

Фильтр находится на странице `/candidates`.

Поля фильтра:

- ФИО;
- город;
- должность;
- навыки;
- возраст от;
- возраст до;
- пол;
- опыт от;
- образование;
- занятость;
- зарплата до;
- сортировка.

Пользователь не обязан заполнять все поля. Это важная часть задания.

В обработчике `Candidates` данные из URL-параметров собираются в структуру `CandidateFilter`:

```go
f := repository.CandidateFilter{
    Name: c.Query("name"),
    City: c.Query("city"),
    Position: c.Query("position"),
    Skills: c.Query("skills"),
    AgeMin: toInt(c.Query("age_min")),
    AgeMax: toInt(c.Query("age_max")),
    Gender: c.Query("gender"),
    ExperienceMin: toFloat(c.Query("experience_min")),
    Education: c.Query("education"),
    EmploymentType: c.Query("employment_type"),
    SalaryMax: toInt(c.Query("salary_max")),
    Sort: c.Query("sort", "experience"),
}
```

Потом вызывается:

```go
a.Repo.SearchCandidates(f)
```

## Как SearchCandidates строит запрос

Функция `SearchCandidates` начинает с базового запроса:

```go
q := r.DB.Model(&models.Candidate{}).Preload("Skills")
```

`Preload("Skills")` нужен, чтобы вместе с кандидатами сразу загрузить их навыки.

Дальше каждый критерий добавляется только если пользователь его заполнил.

Например, если введен город:

```go
q = q.Where("city ILIKE ?", "%"+f.City+"%")
```

Если город пустой, это условие не добавляется.

То же самое для остальных полей:

- ФИО ищется через `full_name ILIKE`;
- город ищется через `city ILIKE`;
- должность ищется через `position ILIKE`;
- минимальный возраст добавляет `age >= ?`;
- максимальный возраст добавляет `age <= ?`;
- пол добавляет `gender = ?`;
- минимальный опыт добавляет `experience_years >= ?`;
- образование ищется через `education ILIKE`;
- тип занятости добавляет `employment_type = ?`;
- максимальная зарплата добавляет `salary_expectation <= ?`.

`ILIKE` используется для поиска без учета регистра. Например, `python`, `Python` и `PYTHON` будут находиться одинаково.

## Пример работы фильтра

Если пользователь указал:

- город: `Екатеринбург`;
- опыт от: `2`;
- зарплата до: `200000`;

то будет построен запрос примерно такого смысла:

```sql
SELECT *
FROM candidates
WHERE city ILIKE '%Екатеринбург%'
  AND experience_years >= 2
  AND salary_expectation <= 200000;
```

Если пользователь оставит поле пола пустым, условие по полу в запрос не попадет.

## Как работает фильтр по навыкам

Навыки обрабатываются отдельно.

Сначала из базы выбираются кандидаты по обычным полям: город, возраст, опыт, зарплата и так далее.

Потом строка навыков из фильтра нормализуется:

```go
requested := service.NormalizeSkills(f.Skills)
```

Затем для каждого кандидата считается количество совпавших навыков:

```go
matches := service.CountSkillMatches(c.Skills, requested)
```

Если пользователь указал навыки, а у кандидата нет ни одного совпадения, кандидат исключается из результата:

```go
if len(requested) > 0 && matches == 0 {
    continue
}
```

Если навыки в фильтре не указаны, кандидаты не отбрасываются по навыкам.

## Как работает сортировка

После поиска результаты сортируются.

Доступные варианты:

- `experience` - по опыту, от большего к меньшему;
- `skills` - по количеству совпавших навыков;
- `salary` - по ожидаемой зарплате, от меньшей к большей;
- `name` - по ФИО по алфавиту.

По умолчанию используется сортировка по опыту.

## Как работает подбор под вакансию

На странице вакансий есть кнопка `Подобрать`.

Она открывает маршрут:

```text
/vacancies/:id/match
```

Обработчик `MatchVacancy`:

1. Находит вакансию по ID.
2. Загружает всех кандидатов вместе с навыками.
3. Передает их в `service.RankCandidates`.
4. Показывает таблицу результатов.

Рейтинг считается в `internal/service/matching.go`.

Максимум - 100 баллов:

- до 60 баллов за совпадение навыков;
- 15 баллов за подходящий опыт;
- 5 баллов за город;
- 5 баллов за тип занятости;
- 5 баллов за образование;
- 10 баллов за зарплатные ожидания в бюджете вакансии.

После расчета кандидаты сортируются по убыванию рейтинга. Если рейтинг одинаковый, выше ставится кандидат с большим опытом.

## CRUD-операции

CRUD означает:

- Create - добавление;
- Read - просмотр;
- Update - редактирование;
- Delete - удаление.

В проекте CRUD реализован для кандидатов и вакансий.

Кандидаты:

- просмотр списка: `GET /candidates`;
- добавление: `GET /candidates/new`, `POST /candidates/new`;
- редактирование: `GET /candidates/:id/edit`, `POST /candidates/:id/edit`;
- удаление: `POST /candidates/:id/delete`.

Вакансии:

- просмотр списка: `GET /vacancies`;
- добавление: `GET /vacancies/new`, `POST /vacancies/new`;
- редактирование: `GET /vacancies/:id/edit`, `POST /vacancies/:id/edit`;
- удаление: `POST /vacancies/:id/delete`;
- открыть или закрыть вакансию: `POST /vacancies/:id/toggle`;
- подбор кандидатов: `GET /vacancies/:id/match`.
